# 编辑器文档生命周期改进（2026-10-20）

本轮处理保存、流程切换和草稿恢复中的数据丢失风险，并把相关行为从 App.tsx 提取为独立模块。

## 问题与改进

| 原设计问题 | 可能发生的结果 | 改进 |
| --- | --- | --- |
| “保存并继续”只看 HTTP 保存是否成功 | 保存期间新增的编辑还没保存，就被后续模板/流程切换覆盖 | 保存提交快照，并比较完成时当前快照；只有当前内容确实已保存才允许继续，否则保留编辑、提示再次保存 |
| 重命名与替换整份文档共用一个保存代次 | 请求已成功保存，但重命名让新修订被忽略；再次保存使用旧基线产生冲突 | 分开加载编辑保护代次与文档生命周期代次；同一文档的名称/参数编辑仍更新成功保存的修订，只把提交内容标记为已保存 |
| 探测基线或等待覆盖确认后不复查文档身份 | 已切换流程，旧保存仍可能提交 | 探测和确认后检查文档 ID 与生命周期代次；切换及 A→B→A 均停止后续写入 |
| 保存回调可以在关闭/丢弃对话框后继续执行 | 旧的“保存并继续”回调可能在用户取消后触发流程切换 | 保存期间显示忙碌状态，禁止对话框取消、丢弃、遮罩和 Esc 关闭；保存失败后恢复操作入口 |
| 草稿只按 600 毫秒防抖 | 最后一次编辑后立即刷新/关闭会漏写；组件卸载也可能丢最后修改 | 正常编辑继续防抖，beforeunload、pagehide、进入后台和真正卸载时补写最新快照 |
| 恢复草稿后立即删除原存储，再等待防抖写回 | 恢复后迅速离开，或新写入失败时，原恢复副本已不存在 | 成功恢复时保留原存储，直到新草稿写入成功或文档保存完成 |
| 草稿写入依赖完整工作流对象引用 | 选中节点或更新运行状态造成等值对象重建时，会不断推迟草稿计时器 | 按序列化文档内容触发防抖，与内容无关的重渲染不重置计时器 |
| 保存和草稿规则集中在 App.tsx | 很难独立模拟网络延迟、文档切换和页面离开事件 | 提取 useWorkflowSave、useWorkflowDraft，App 只负责装配、覆盖确认和保存快照状态 |

## 保留的行为

- 后端基线乐观并发校验、无基线时的探测和覆盖确认、15 秒网络超时均保留。
- 网络中断后的写入结果继续视为未确认，不将其错误描述为确定没有提交，也不自动重试写入。
- 草稿仍使用已有 version=1 格式和存储键，无迁移要求；待恢复入口存在时不覆盖旧草稿。
- 待恢复入口存在时，如果当前文档又发生编辑，刷新/关闭确认仍然生效。
- 不改变运行与调试执行器、工作流文件格式或后端 API。

## 缺失修订号的处理

- 从载入响应获得的空白修订号表示“基线未知”，不代表远端文档不存在。只有探测返回 HTTP 404 才允许发送空的 `expectedRevision` 新建基线。
- 探测到已有文档但响应缺少有效 `X-Workflow-Revision` 时，停止保存并提示检查后端/代理，不再请求覆盖确认或发送写入。
- PUT 成功但修订头缺失时，仍记录提交快照已保存，同时清除旧基线并给出警告。下一次保存必须重新探测并确认覆盖，不能沿用旧修订或误走新建流程。保存期间新增的编辑仍保持未保存状态。
- 专项回归覆盖空字符串、纯空白修订、缺失响应头，以及再次保存的探测、确认与新修订绑定。

草稿测试验证连续编辑防抖、正常关闭/刷新、后台切换、卸载补写、待恢复保护、恢复副本保留、保存后清除、存储故障提示及等值重渲染。

验证结果：相关 36 项回归通过；前端全量 50 个文件、665 项测试通过；TypeScript、生产构建、静态审计和 diff 格式检查通过。App.tsx 从 2248 行减少至 2123 行，保存与草稿行为可分别测试。

## 工作流校验与核心 DSL 请求（后续改进）

将校验和 DSL 检查从 [App.tsx](../frontend/src/App.tsx) 提取到 [useWorkflowInspection.ts](../frontend/src/useWorkflowInspection.ts)，不改变后端编译器、工作流格式或执行器。

| 原设计问题 | 改进 |
| --- | --- |
| 多次点击并发提交，旧请求能覆盖新报告或弹出旧 DSL | 校验与编译分别同步互斥，互不阻塞；结果必须仍属于当前请求、文档快照、文档生命周期代次和节点目录 |
| 编辑、切换流程或载入同内容文档后，旧请求仍会展开问题面板、发通知 | 上下文变化取消旧请求；迟到的成功、失败和 finally 均不能修改或释放新请求。A→B→A 也不能让已失效请求恢复归属 |
| 编译结果没有快照归属，关闭后迟到正文可能重新打开弹窗 | 编辑、目录变化、文档替换、关闭和重置均使旧 DSL 失效；卸载后不再落地或通知 |
| 请求或正文不响应 abort 时没有等待上限 | 复用 [withRequestTimeout](../frontend/src/requestTimeout.ts)，为网络请求及成功/错误正文共用 15 秒期限；到期实际结束等待并解除忙碌状态，不自动重试 |
| HTTP 200 空对象也可能被视为校验成功，非法 DSL 被当作原文展示 | 校验要求明确的 valid=true 和有效节点列表，统计值若存在必须为非负安全整数；DSL 必须是有效 JSON 流程定义，不能用无效响应生成成功结果 |
| 错误仅读取 error，丢失 ProblemDetails 原因和关联号 | 复用统一错误适配器，保留 detail、code、correlationId，同时兼容原有 valid=false/error 交互式校验结果 |

保留已有客户端参数/连线预检、可定位问题列表、成功统计和格式化 DSL 弹窗。已完成的校验在同一文档编辑后仍保留报告，并显示“需要重新校验”；切换文档则恢复未校验。等值文档对象重建不会取消请求。模块展开后的节点数不必等于画布节点数；旧响应未提供的可选统计不再虚报为零。

新增 44 项模拟网络回归；首批 34 项在原逻辑提取后有 30 项失败，修复后全部通过。覆盖同步防重、独立请求、慢正文、过期响应、请求重叠、文档代次、目录变化、A→B→A、等值对象、关闭/重置/卸载、网络与 JSON 故障、响应契约及模块展开。期限测试分别检查 14,999 毫秒仍在等待、15,000 毫秒结束，并验证忽略取消的迟到响应不能覆盖重试结果。与共享期限、错误适配器、节点校验、文档导入和保存合计 6 个文件、110 项测试通过；TypeScript、生产构建和静态审计通过。构建仍有既有大包体告警，未在本轮修改打包策略。
