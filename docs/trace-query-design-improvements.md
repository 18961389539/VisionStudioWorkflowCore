# 追溯查询设计改进（2026-10-20）

本轮从项目结构、编辑器状态管理和追溯查询链路入手，优先修复能导致错误数据展示、请求循环和交互误导的问题。节点参数目录已有专门的逐节点审查记录，本轮不重复该部分。

## 已修复的问题

| 问题 | 影响 | 改进 |
| --- | --- | --- |
| 只在响应头返回后检查请求代次 | 切换筛选后，旧响应正文、旧错误正文或旧统计仍可能晚到并覆盖新状态 | 每个请求在正文解析完成后检查自身生命周期；切换筛选、关闭和卸载统一取消并使结果失效 |
| 按筛选对象引用触发刷新 | 相同字段的新对象会重复触发请求；与状态更新结合可形成循环 | 用筛选字段构造稳定依赖，相同值不重复请求 |
| 列表、统计、存储通过一个 Promise.all 成败绑定 | 一个辅助接口网络故障会丢弃成功列表；辅助接口挂起时列表也无法展示 | 三个资源独立加载，列表成功即可展示，辅助失败单独提示并支持重试 |
| 超时与生命周期取消都静默忽略 | 后端慢响应会表现为查询没有结果、没有原因 | 保留 20 秒期限；超时显示原因和重试入口，正常关闭保持安静；清理请求及定时器 |
| 保留旧数据，却显示新筛选范围和旧统计 | 用户可能把上一次结果误认为当前查询结果；统计失败被伪装为 0 | 明确标记上次结果，保留原范围和更新时间；当前列表未成功前隐藏新统计，缺失数据用“—”占位 |
| 时间框截取 UTC ISO 前 16 位 | datetime-local 显示 UTC 数字，但提交又按本地时间解析；北京时间下编辑会偏移 8 小时 | 本地日历字段显示、本地输入转 UTC 提交，补充倒置/无效时间校验；允许单侧时间窗 |
| 列表、统计和范围说明各取一次当前时间 | 最近一小时边界有毫秒差；跨午夜时可能查不同日期；重渲染会让说明漂移 | 同次查询共用时间快照，范围说明随成功列表落地 |
| 空自定义筛选存在两套默认口径 | 列表查询全部历史，统计却默认近 7 天 | 无有效筛选时前端发送 allTime=true，后端使用无时间限制的相同过滤谓词 |
| 用固定毫秒数倒推日历日期 | 部署在有夏令时的时区时，“昨天”或“最近 7 天”可能偏一天 | 按本地日历增减日期后取零点 |

## 接口与兼容性

- 新增可选查询参数：`GET /api/traces/stats?allTime=true`。该参数取消旧版默认的近 N 天窗口，其它显式筛选仍然生效。
- 不带参数、`allTime=false` 和原有 `days` 调用保持原行为；已有带筛选的调用保持原行为。
- 无数据库迁移。新的前端与后端应一起发布，运行实例需要加载本次后端构建。
- 列表和统计仍是独立请求。它们共用筛选和时间边界，但持续写入期间不保证数据库事务级的同一瞬时快照。

## 验证范围

回归覆盖慢正文倒序、旧错误与旧统计、关闭/卸载取消、超时重试、辅助接口网络/HTTP/JSON 失败、辅助挂起时列表先显示、旧结果标记、相同筛选去重、共享时间边界、本地时间往返、时间范围校验、夏令时日历边界及全部历史接口兼容性。另检查前端类型与生产构建、OpenAPI 契约和仓库静态审计。

验证结果：前端全量回归通过（48 个文件）；最后补充的同筛选显式刷新与其它界面交互共 5 项通过；追溯分页及 OpenAPI 相关 API 测试 10 项通过；America/New_York 时区下的 19 项时间查询测试通过；TypeScript、生产构建、静态审计及 diff 格式检查通过。

## 后续结构性改进

`App.tsx` 仍集中了承载画布、文档保存、草稿恢复、历史记录和多个业务入口，修改牵连面较大。后续适合按文档生命周期、画布交互和工作区布局逐步提取模块，每次保留行为验证。本轮只记录这个维护问题，不在修复查询正确性的同时进行大范围搬迁。
