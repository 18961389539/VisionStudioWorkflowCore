# 参数调优工作区设计改进（2026-10-20）

本轮处理离线预览与当前参数不一致、数据集切换混入旧响应、验证启动重复提交和候选载入覆盖编辑的问题。

## 问题与改进

| 原设计问题 | 影响 | 改进 |
| --- | --- | --- |
| 只有发出下一次预览请求才增加 previewSeq | 参数变化后的 550 毫秒防抖期间，旧响应仍可被接纳；关闭自动预览后旧指标一直看起来有效 | 参数、ROI、节点、样本或候选代次变化立即使旧结果失效并取消旧请求；防抖只延迟下一次自动请求 |
| 图像 URL 单独保存在状态中，只清结果不清图像 | 换数据集、样本或节点后仍可能显示上一上下文的图 | 图像绑定样本来源及节点；切换上下文立即隐藏。相同样本与节点的上次背景可保留供 ROI 编辑，但明确标为过期，旧叠加与指标不作为当前结果展示 |
| 自动节点预览与手动完整流程预览互相覆盖 | 用户刚运行完整流程，迟到的自动节点预览抹掉分类结果 | 手动操作取消待发自动任务，并可取代在途自动请求；旧请求不能覆盖新结果，界面明确区分节点与完整流程模式 |
| 自动预览静默吞掉异常，成功响应缺少契约检查 | 自动预览不更新却没有原因，空对象或错误来源可进入结果区域 | 自动与手动失败均在界面保留具体原因、错误码和关联号；核对样本、来源、节点、运行模式及报告结构，完整的算法失败结果仍正常展示 |
| 数据集详情与记录使用 Promise.all，选择变化不取消读取 | 慢详情阻塞验证记录，A 的响应可能覆盖 B 的样本、记录和预览 | 列表、详情、验证记录独立读取；按资源保存所有权，切换立即取消。即便同事件内 A → B → A，也重新建立读取上下文 |
| 每次记录变化都会重建轮询并重新读取详情 | 慢请求可能重叠，样本选择被轮询闭包覆盖 | 仅存在 Running 任务时轮询记录，每秒检查且在途跳过；详情独立读取，保留仍然可重放的样本选择，已移除样本自动失效 |
| POST 验证只靠 React loading 防止重复 | 同一事件可以创建重复验证，启动异常还可能成为未处理拒绝 | 使用同步操作锁；验证与候选读取分别持有请求身份、期限和错误。最近确认的提交仍运行时禁止原样重复提交，编辑后的新快照仍可另行验证 |
| 验证请求与持续编辑的候选没有明确关系 | 参数已经改变，刚启动的验证可能被理解为覆盖了当前修改 | 验证固定提交快照；等待期间继续编辑时，明确显示当前参数与验证快照不同，验证记录仍指向原提交 |
| 网络失败后无法判断验证是否已经创建 | 直接重试可能创建重复任务 | 每次提交带唯一来源标识，用既有 sourceWorkflowRunId 字段核对记录；未确认时禁止直接重提。找到对应记录则恢复任务状态；未找到时，成功刷新记录并由用户明确核对后，才允许再次手动提交 |
| 收到创建确认后，旧 GET 仍可替换验证列表 | 刚创建的任务突然消失，进度轮询停止 | 创建确认使旧读取失效；暂未出现在新读取中的已确认任务保留，直到记录列表观察到它 |
| 候选工作流 GET 不检查本地编辑或窗口关闭 | 用户新输入被迟到候选覆盖，或关闭后仍报成功 | 候选读取绑定数据集、候选内容与编辑代次；编辑、重置、换数据集、关闭和卸载使旧响应失效；结构有效且来源仍有效时才载入与报成功 |

## 实现与边界

- `useTuningPreview` 管理预览内容、图像归属、550 毫秒防抖、60 秒期限和请求取消。
- `useTuningData` 管理独立的列表、详情和记录读取，读取期限为 15 秒；可用样本与读取错误参与预览入口判断。
- `useTuningCandidates` 管理 20 秒验证启动、15 秒候选读取、提交快照与未确认结果的核对；写入不自动重放。
- `tuningContracts` 检查工作区所使用的数据契约；执行结果结构检查从 `useRunController` 原样移至共享 `runResult`，避免两处接受不同形状的运行报告。
- 未确认任务的来源标识用于读取核对，不是后端幂等键。再次提交仍是明确的新请求；关闭界面或取消 HTTP 不保证撤销已创建的后台验证任务。
- 上次图像背景不被当作新参数的执行证据；它的旧叠加、节点摘要和分类指标在编辑后失效，便于继续绘制 ROI 并等待新结果。
- 参数控件增加可访问名称；工作区标题移除固定的 V0.49 字样，避免与应用版本混淆。
- 本轮不改变验证执行器、后端接口、数据集格式或 A/B 指标计算方式。

## 请求期限与恢复补充（2026-10-21）

- 原期限只调用 `AbortController.abort()`，加载状态与同步锁仍等待底层请求或正文完成。如果取消没有及时结束等待，界面会一直忙碌，无法重试；验证启动也不能及时进入“结果未确认”状态。
- 三个调优 hook 共用 `withRequestTimeout`，对完整请求及成功/错误正文设置等待期限。到期或所属上下文取消时立即结束等待，清理计时器和取消监听器；底层忽略取消后迟到的成功或失败也不会再次提交结果、解锁其它请求或产生未处理拒绝。
- 保持既有期限：数据集列表、详情、验证记录及候选读取 15 秒，验证启动 20 秒，离线预览 60 秒。读取与预览超时后显示原因并允许恢复，不保留失效的加载锁。
- 验证 POST 超时仍不证明后端未创建任务：结束加载后保留未确认状态与重复提交保护，仅刷新记录核对唯一提交标识，不自动再次写入。已经收到明确 HTTP 拒绝时，即使错误正文超时，也不会误报可能创建任务。
- 不改变候选快照归属、自动预览防抖、算法失败报告展示或已有的人工核对流程。
