# 流程载入与编辑应用设计改进（2026-10-20）

本轮统一编辑器的文档替换入口，区分“打开另一份文档”和“在当前文档上应用编辑”，处理配方载入、模块提取、模块内部编辑及参数调优的归属问题。

## 问题与改进

| 原设计问题 | 影响 | 改进 |
| --- | --- | --- |
| 只有模板和已保存工作流载入检查未保存状态；配方、模块与草稿恢复直接 restore | 未保存内容可能被其它入口直接覆盖 | 文档替换统一通过 useWorkflowChanges；有修改时提供取消、丢弃、保存并继续，实际应用结果以 Promise<boolean> 返回 |
| 配方异步载入没有绑定请求发出时的设计器内容 | 读取期间的参数、位置或名称编辑可能被迟到响应覆盖 | 请求开始即捕获文档代次和完整内容快照；读取正文之后及最终应用之前都核对来源 |
| 原载入保护依赖 nodes/edges 引用与额外的手动加载代次 | 与内容无关的重渲染容易误判为编辑，名称等编辑又容易漏加失效标记 | 统一用完整文档序列化内容和文档生命周期代次，名称、参数、位置自动纳入保护；同内容的 A → B → A 仍因代次变化而失效 |
| 静态回调不能得知用户最终是否接受载入 | 取消后仍可能显示“已加载”，或错误设置模块编辑来源 | 配方与模块只在实际应用返回 true 后更新绑定、编辑来源和成功反馈；面板关闭或切换来源会取消未决确认 |
| 已保存流程在读取前就要求丢弃修改 | 用户尚不知道目标能否读到，就必须先处理当前修改 | 先完成读取、结构和身份核对，再展示未保存确认；读取失败不改变画布 |
| 调优、模块提取与打开文档共用整块恢复逻辑 | 清空撤销历史、丢失保存修订，并将尚未保存的编辑误标为已保存 | 将它们作为同一文档的编辑，记入撤销历史，保留保存基线、文档身份与未保存状态；保留仍存在的选中节点、断点和视口 |
| 调优候选长期保留打开时的副本，应用时不核对源流程 | 设计器后来发生编辑，旧候选会把这些编辑一起覆盖 | 调优和提取以源快照为前提；源已变化时拒绝套用。调优可通过“还原为设计器版本”重新建立候选基线 |
| 提取模块把远端创建与本地替换混成一个成功状态 | 模块已创建，但设计器已变更时，可能仍覆盖画布或误报整个操作失败 | 分别反馈创建与替换结果；远端创建成功但本地不能应用时保留当前编辑，并提示从模块库查看新模块 |
| 模块编辑来源仅记录 editingModuleId | 打开模块后再切换其它文档，仍可能把其它流程保存成该模块的新版本 | 编辑来源绑定文档生命周期；同一文档允许继续编辑，整块切换后必须重新打开目标模块 |
| 保存并继续依赖渲染后的 busy 状态与旧闭包 | 同一事件的重复确认或取消可与保存回调交错 | 确认与保存共用同步所有权；取消来源、换确认对象或卸载后，旧保存回调不能执行后续切换 |
| 模块读写缺少关闭取消、正文检查和明确的失败反馈 | 迟到响应可更新已关闭面板或替换画布；请求挂起无法结束 | 读取 15 秒、模块写入 20 秒期限；同步阻止重复写入，关闭取消并忽略迟到响应；写入不自动重试 |

## 实现与行为边界

- `useWorkflowChanges` 管理文档确认、来源快照、候选副本和应用结果。`replace` 走未保存确认；`edit` 只允许来源仍未变化且文档 ID 一致的候选，不丢弃已有编辑，不绑定候选提供的后端修订。
- `useWorkflowImport` 管理配方与已保存工作流读取，以及已解析的有效流程载入。请求、正文、来源和最终应用各阶段均有检查；人工确认等待不占用网络读取期限。
- `workflowDocument` 在进入图恢复之前检查可载入结构。已保存流程还核对响应 ID，配方快照核对 jobId 和 version；算法与连线语义继续由既有工作流校验负责。
- 图数据构建完成后才切换文档身份和修订，避免构建异常留下身份已变、画布未变的半应用状态。
- 配方、模块内部流程属于外部来源，载入后不会冒充已保存到工作流文件接口；仅从工作流文件接口实际载入时绑定其修订并标为已保存。
- 模板、草稿恢复及文件载入仍属于文档替换，会重建撤销时间线。调优与模块提取可撤销，但仍清理旧执行结果并要求重新校验。
- 模块写入可能在网络中断前已提交；取消 HTTP 请求不等于撤销服务端创建，需核对模块库或版本列表后再操作。
- 不修改后端接口、工作流/模块文件格式、运行时执行器或设备动作授权。

## 补充边界修复

- 文档结构校验拒绝空白节点类型、节点/连线 ID、连线端点及端口名，并拒绝同类元素的重复 ID，防止画布选择、更新或删除发生身份歧义。节点与连线使用独立、区分大小写的 ID 空间；未知插件、悬空连线及环路仍交给既有语义校验，不在载入阶段新增限制。校验不自动重命名或丢弃元素。
- 流程成功应用之后，`onApplied` 回调失败不再返回“未载入”或声称“当前设计器保持不变”。接口仍返回 `true` 表示文档确已应用，同时明确提示后续处理失败，避免重复载入。
- 新增结构测试和导入生命周期回归，覆盖重复/空白标识拒绝、兼容边界，以及应用后的回调异常。

## 验证

专项回归覆盖取消、丢弃、保存失败/成功、同步重复确认、保存期间编辑、来源关闭、确认替换、卸载、A → B → A、重命名/位置/参数变化、候选快照固定、无效响应、请求超时、配方身份核对、迟到正文、模块编辑来源、提取结果分开反馈及调优重新建立来源。网络与模块写入均使用模拟响应，没有操作现场设备或创建真实服务端模块。

验证结果：47 项专项回归通过（本轮新增 40 项）；前端全量 59 个文件、807 项测试通过。TypeScript、生产构建、静态审计与 diff 格式检查通过；构建仍有现有的大包体积提示。
