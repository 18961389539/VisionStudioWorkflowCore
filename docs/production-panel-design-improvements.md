# 生产面板配置与刷新设计改进（2026-10-20）

本轮处理生产配置被轮询覆盖、未保存配置与运行入口混用，以及生产面板读取和写入的生命周期。

## 操作员界面与多工位部署

运行宿主首页或 `/?view=operator` 打开操作员界面。登录后可查看当前配方和版本、开始或停止生产、恢复运行与确认报警。

车间大屏用 `/?view=operator&kiosk=1`：不渲染标签栏、页面标题、诊断按钮与账号徽标，尺寸按视口短边（vmin）缩放（1080p 下判定字号约 119px、≤768p 约 84px），三张指标卡横向铺满剩余高度、标题固定在卡片顶部对齐；布局读取失败时静默回落到默认三卡，不把技术错误挂在操作员面前。退出 kiosk 只需去掉 `kiosk` 参数。

生产状态读取失败时保留最后一次成功读取的数值，在工作台上方显示“数据已过期 · 数字为 HH:MM:SS 的最后一次读取值，不是实时值”，并把状态标签降为灰色、整组指标降饱和；**不用破折号顶替**——车间里一条破折号会被读成“今天零产量”，比显示旧值更危险。恢复读取后横幅与降级视觉自动消失。在设计宿主的生产面板中，工程师可为每个配方配置面板标题，勾选并排序最近判定、产量与良率、节拍和告警组件。布局随系统备份的 `production-config` 段恢复。

多工位总览可从生产面板进入，也可直接打开 `/?view=stations`。它显示连接状态、最新运行状态、生产与告警计数、已发布和运行中的版本。断连后保留上次数据，版本核验回到待核验。核验目标可包含流程 SHA-256，以区分本地版本号相同而内容不同的配方。工位链接在新窗口打开该工位的操作员页面，操作员使用工位自己的登录会话。

同一个工位仍然一次只锁定并运行一个工作流；“多工作流并行”通过多个独立工位实现。总览可一次选择最多 8 个在线且已配置控制权限的工位并发启动或停止。启动使用各工位自己的已保存生产配置，不允许总览替工位临时选择其它配方。离线、未配置控制令牌和当前状态不适用的工位不会进入请求，逐工位结果明确区分成功与失败；一个工位失败不会回滚其它已经执行的工位。

**现场配置**

多工位页提供「生成工位配置」向导（空态与工具栏均可进入）：按后端 `ProductionStationOptions.IsValid` 同一套规则校验工位 ID、地址协议（跨主机必须 https）、令牌前缀与"期望版本必须与配方 ID 成对"，生成可直接粘贴的 `ProductionFleet.Stations` 片段与按列表下标绑定的令牌环境变量。向导只生成文本、不写配置文件，也不会把令牌发送到后端；界面内明确提示"配置在启动时校验，漏配令牌会让宿主拒绝启动"。

1. 在每个工位的 `site-config/appsettings.site.json` 中设置 `ProductionFleet:StationId`，例如 `inspection-a`。重启工位后，用管理员会话分别创建独立的只读令牌 `stations:read`，以及需要总览启停时的 `stations:control` 令牌。
2. 在总览宿主的站点配置中登记工位。跨主机使用 HTTPS，测试时可连接本机 HTTP。

```json
{
  "ProductionFleet": {
    "Stations": [
      {
        "Id": "inspection-a",
        "Name": "正面检测",
        "BaseUrl": "https://inspection-a.example/",
        "ExpectedJobId": "front-cover",
        "ExpectedVersion": 4
      }
    ]
  }
}
```

3. 为每个站点条目设置总览宿主的环境变量 `ProductionFleet__Stations__0__Token`，需要远程启停时再设置 `ProductionFleet__Stations__0__ControlToken`（按列表索引递增），再重启总览宿主。三个权限用途的令牌必须彼此不同。可选版本目标需要同时指定 `ExpectedJobId` 和 `ExpectedVersion`，也可补充 `ExpectedWorkflowHash`。预期版本变化时更新总览配置并重启。告警确认和故障恢复仍在对应工位完成。

### 配方分批下发与接收

1. 在目标工位用管理员创建仅含 `stations:deliver` 的服务令牌。在总览宿主通过 `ProductionFleet__Stations__0__DeliveryToken` 关联到同一个工位索引，并保留独立的 `stations:read` 和可选 `stations:control` 令牌。配置后重启总览宿主。
2. 在设计宿主打开「多工位 → 配方分批下发」，选择一个当前已发布版本和最多 8 个工位。批次记录保存逐站的接收、拒绝和未确认结果，成功回执包含工位本地版本。未确认的工位可再次选择发送，同一来源版本、流程指纹和验证要求的重复投递会复用回执。
3. 在目标站「配方收件箱」核对并发布本地草稿。受数据集验证门禁约束的版本先在站点设计端关联通过的验证，再执行发布。站点发布会重新捕获本地运行依赖并应用节点成熟度确认。工位本地版本号由该工位分配，批次回执显示来源与本地版本的映射。
4. 下发包携带已解析参数的工作流和校验指纹。相机、PLC、模型、模块和标定等依赖由各工位配置。正在运行的会话继续使用其锁定版本，切换在下次启动生效。新配方首次使用时，仍需在站点设计端设为生产作业。总览的版本目标按工位的本地版本号配置，可同时填写流程指纹。

操作员工作台默认布局为「最近判定 / 产量与良率 / 检测节拍 / 活动告警」四张卡（`OperatorLayout.Default` 与前端兜底同步）。告警卡显示活动数、待确认数与严重数，并给出**最近一条告警内容**；有严重告警时卡片用红色边框与红色标题标出，只有普通活动告警时用警告色，统计读取失败时不保留上一轮的严重级颜色。kiosk 形态下顶部不再显示"查看待确认告警"按钮——没有标签栏可跳，按钮点了不会有反应。

操作员布局可选「最近检验留图」，并可切换到「最近不合格」。两种视图沿用已有留图策略，图像来自当前生产会话和锁定版本。开始新会话或停止后会清除上次会话的图像。

### 工作台告警与下发进度

- 操作员工作台显示最近三条待确认的活动告警，可就地确认，也可打开告警页处理完整列表。确认后的告警在恢复前仍计入活动告警。
- 多工位总览可按工位或配方搜索，并将故障、严重告警和版本问题排在前面。设计端工程师可直接查看各工位历史上最新的一次下发，并按待发布、待切换或已切换运行筛选。批次对话框展示最近 30 批次。发布和运行进度按工位本地版本及流程指纹核验，离线或采样早于下发时显示待核验。
- 从批次记录可重选拒绝或未确认的工位。重选只填写本批草稿，工程师核对后再下发。来源已发布版本或指纹变化时需重新选择配方。

## 问题与改进

| 原设计问题 | 影响 | 改进 |
| --- | --- | --- |
| 每次轮询直接 setConfig，表单与服务端快照共用状态 | 用户输入的周期延迟、保护参数或作业选择会在下一次刷新时消失 | 服务端配置与编辑副本分离；有修改时保留草稿，实时监控继续刷新 |
| 启动请求从表单取 jobId，而后端从已保存配置读取其它参数 | 未保存时可能用新作业配上旧参数启动，界面与实际运行不一致 | 有未保存修改时禁用启动和恢复；保存确认后再允许启动 |
| 默认配置从首屏就能保存 | 首次读取失败时可能把展示默认值写回后端，重置现场参数 | 配置与生产状态读取成功之前禁止编辑和保存；无效成功响应按读取失败处理 |
| 保存成功后无法区分提交快照与等待期间新增编辑 | 后来输入的值可能被抹掉，或被误标为已保存 | 只确认提交快照；后续输入保留为未保存，使用新的保存基线继续编辑 |
| 外部配置改变时静默替换输入 | 用户无法知道自己的编辑依据已过期 | 保留原草稿并提示冲突，暂禁保存；提供“放弃修改，载入最新配置”的明确入口 |
| 辅助 fetch 共用 allSettled，正文按顺序解析 | 慢配置阻塞所有辅助数据；前一个正文损坏会跳过告警和待核对动作处理 | 状态、配置、配方、告警与待核对动作分别轮询、解析、限时与提交；各自保留读取错误 |
| 辅助失败被吞掉；已有待核对记录时不显示读取失败 | 陈旧记录看起来仍然实时，读取失败容易被理解为没有待核对动作 | 失败保留最后成功数据并显示降级；仅 pending 端点明确返回 204 时清除清单 |
| 请求布尔锁在旧 finally 中无条件释放，关闭时又未立即重置 | 重开时等待旧请求；旧请求结束还可能让新请求失去互斥 | 按资源保存请求所有权；关闭取消并释放，旧正文、旧超时和旧 finally 均不能影响新请求 |
| 写操作只用 React busy 标识且没有请求期限 | 连续点击可重复发送，挂起后操作入口不恢复，迟到成功可能更新已关闭面板 | 按动作使用同步请求锁，20 秒取消期限，关闭后忽略响应；保存与启动同步互斥 |
| 启动和停止的响应可能倒序到达 | 已停止后，迟到的启动确认又显示运行和成功提示 | 运行操作记录代次，旧确认不覆盖后续操作；停止仍可在其它请求等待时调用 |
| 核对窗口依赖实时 pendingActions，校验字段时尚未进入忙碌状态 | 后台刷新可能换掉实际提交对象；校验期间关闭或重复确认仍可留下提交 | 打开时固定核对目标并显示运行 ID；从字段校验开始同步加锁，关闭使旧校验失效，失败保留窗口 |
| 8 个标签同层：操作员/监控/告警/多工位/收件箱/生产配置/PTP/同步健康 | 操作与配置语义混在一处，找「PTP 保护」要扫过整排；操作员与工程师面对同一排入口 | 分「运行」「配置」两组：工程师默认停在运行组，配置类收敛到第二组；操作员（无配置权限）不渲染分组控件，只看得到运行标签 |

## 实现与边界

- `useProductionMonitor` 管理五类读取的独立生命周期，保留 1 秒节拍、5 秒读取期限，并在请求与正文两个边界检查所有权和取消状态。
- `useProductionConfigDraft` 管理编辑基线、修改、冲突和保存确认；补丁按最新副本合并，同一事件内修改不同字段不会相互覆盖。
- `useProductionActions` 管理写请求、错误与忙碌状态；失败信息保留错误码和关联号，网络、超时、无效成功响应及 5xx 均提示结果未确认，不自动重试写入。
- 服务端返回但表单未暴露的标量字段仍随配置保留，例如 `maxRecoveryAttempts`；编辑周期延迟不会重置这些字段。
- 已确认的配置和状态写响应会使此前的对应 GET 失效，旧 GET 正文不能覆盖刚确认的写入。
- `GET /api/production/config` 在响应头返回配置的 `ETag`。保存时将其放入 `If-Match`，服务端在写入锁内比较修订。缺少基线返回 428，修订冲突返回 409。面板按编辑基线、草稿和最新配置比较字段。不同字段的修改可以合并，同一字段的不同修改需要逐项选择。合并只更新草稿，保存时使用最新修订。
- 告警总览显示待确认入口。列表支持全部、活动和待确认筛选，按筛选后的总数分页。待确认只包含仍活动且未确认的告警，确认后刷新列表与总览。
- 草稿保存在当前面板实例中。本轮不新增生产配置的本地持久化，也不改变编辑器配方载入流程。

## 轮询与保存交错补充（2026-10-21）

- 原草稿只按开始编辑时的基线判断是否修改。保存的 PUT 响应慢于 GET 轮询时，用户改回原值可能被误认为放弃编辑，输入被替换成已提交值；远端已经与草稿完全一致时，也可能一直保留旧基线并误报冲突。
- “是否仍有未保存差异”与最新已读取配置比较；“是否需要核对外部变化”仍与开始编辑时的基线比较。界面与同步读取使用同一判断，不能出现界面允许启动而回调又判为冲突的分歧。
- 普通草稿与远端完全一致后清除旧编辑归属，后续刷新正常跟随服务端，下一次编辑使用新基线。远端已经改变时，输入原基线值仍保留为待核对编辑，不再静默切换为远端值；主动改成最新远端值则解除冲突。
- 保存开始同步建立独立归属，保存期间的后续输入即使等于旧远端值也保留。覆盖轮询在该输入之前、之后两种顺序；成功只确认提交快照，后续修改仍需再次保存，不能提前启动生产。
- 保存结果未确认时，不因结束等待就丢弃期间的新意图；迟到的远端变化仍保留输入并要求核对。关闭、重开释放旧保存归属，旧结束回调不能清除新保存的归属；保留现有写操作互斥、错误提示和放弃修改入口。
- 本补充只修改前端草稿与保存衔接，不改变后端保存、运行时锁或现场操作；仍不提供跨客户端的原子修订比较。
