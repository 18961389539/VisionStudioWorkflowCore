# 生产面板配置与刷新设计改进（2026-10-20）

本轮处理生产配置被轮询覆盖、未保存配置与运行入口混用，以及生产面板读取和写入的生命周期。

## 问题与改进

| 原设计问题 | 影响 | 改进 |
| --- | --- | --- |
| 每次轮询直接 setConfig，表单与服务端快照共用状态 | 用户输入的周期延迟、保护参数或作业选择会在下一次刷新时消失 | 服务端配置与编辑副本分离；有修改时保留草稿，实时监控继续刷新 |
| 启动请求从表单取 jobId，而后端从已保存配置读取其它参数 | 未保存时可能用新作业配上旧参数启动，界面与实际运行不一致 | 有未保存修改时禁用启动和恢复；保存确认后再允许启动 |
| 默认配置从首屏就能保存 | 首次读取失败时可能把展示默认值写回后端，重置现场参数 | 配置与生产状态读取成功之前禁止编辑和保存；无效成功响应按读取失败处理 |
| 保存成功后无法区分提交快照与等待期间新增编辑 | 后来输入的值可能被抹掉，或被误标为已保存 | 只确认提交快照；后续输入保留为未保存，使用新的保存基线继续编辑 |
| 外部配置改变时静默替换输入 | 用户无法知道自己的编辑依据已过期 | 保留原草稿并提示冲突，暂禁保存；提供“放弃修改，载入最新配置”的明确入口 |
| 辅助 fetch 共用 allSettled，正文按顺序解析 | 慢配置阻塞所有辅助数据；前一个正文损坏会跳过告警和待核对动作处理 | 状态、配置、配方、告警与待核对动作分别轮询、解析、限时与提交；各自保留读取错误 |
| 辅助失败被吞掉；已有待核对记录时不显示读取失败 | 陈旧记录看起来仍然实时，读取失败容易被理解为没有待核对动作 | 失败保留最后成功数据并显示降级；仅 pending 端点明确返回 204 时清除清单 |
| 请求布尔锁在旧 finally 中无条件释放，关闭时又未立即重置 | 重开时等待旧请求；旧请求结束还可能让新请求失去互斥 | 按资源保存请求所有权；关闭取消并释放，旧正文、旧超时和旧 finally 均不能影响新请求 |
| 写操作只用 React busy 标识且没有请求期限 | 连续点击可重复发送，挂起后操作入口不恢复，迟到成功可能更新已关闭面板 | 按动作使用同步请求锁，20 秒取消期限，关闭后忽略响应；保存与启动同步互斥 |
| 启动和停止的响应可能倒序到达 | 已停止后，迟到的启动确认又显示运行和成功提示 | 运行操作记录代次，旧确认不覆盖后续操作；停止仍可在其它请求等待时调用 |
| 核对窗口依赖实时 pendingActions，校验字段时尚未进入忙碌状态 | 后台刷新可能换掉实际提交对象；校验期间关闭或重复确认仍可留下提交 | 打开时固定核对目标并显示运行 ID；从字段校验开始同步加锁，关闭使旧校验失效，失败保留窗口 |

## 实现与边界

- `useProductionMonitor` 管理五类读取的独立生命周期，保留 1 秒节拍、5 秒读取期限，并在请求与正文两个边界检查所有权和取消状态。
- `useProductionConfigDraft` 管理编辑基线、修改、冲突和保存确认；补丁按最新副本合并，同一事件内修改不同字段不会相互覆盖。
- `useProductionActions` 管理写请求、错误与忙碌状态；失败信息保留错误码和关联号，网络、超时、无效成功响应及 5xx 均提示结果未确认，不自动重试写入。
- 服务端返回但表单未暴露的标量字段仍随配置保留，例如 `maxRecoveryAttempts`；编辑周期延迟不会重置这些字段。
- 已确认的配置和状态写响应会使此前的对应 GET 失效，旧 GET 正文不能覆盖刚确认的写入。
- 本轮不改变后端运行时、接口或设备授权。外部配置冲突根据已读取的配置识别，现有 PUT 接口仍未提供原子的修订比较；读取后、提交前的跨客户端竞争需要后端并发契约另行处理。
- 草稿保存在当前面板实例中。本轮不新增生产配置的本地持久化，也不改变编辑器配方载入流程。

## 轮询与保存交错补充（2026-10-21）

- 原草稿只按开始编辑时的基线判断是否修改。保存的 PUT 响应慢于 GET 轮询时，用户改回原值可能被误认为放弃编辑，输入被替换成已提交值；远端已经与草稿完全一致时，也可能一直保留旧基线并误报冲突。
- “是否仍有未保存差异”与最新已读取配置比较；“是否需要核对外部变化”仍与开始编辑时的基线比较。界面与同步读取使用同一判断，不能出现界面允许启动而回调又判为冲突的分歧。
- 普通草稿与远端完全一致后清除旧编辑归属，后续刷新正常跟随服务端，下一次编辑使用新基线。远端已经改变时，输入原基线值仍保留为待核对编辑，不再静默切换为远端值；主动改成最新远端值则解除冲突。
- 保存开始同步建立独立归属，保存期间的后续输入即使等于旧远端值也保留。覆盖轮询在该输入之前、之后两种顺序；成功只确认提交快照，后续修改仍需再次保存，不能提前启动生产。
- 保存结果未确认时，不因结束等待就丢弃期间的新意图；迟到的远端变化仍保留输入并要求核对。关闭、重开释放旧保存归属，旧结束回调不能清除新保存的归属；保留现有写操作互斥、错误提示和放弃修改入口。
- 本补充只修改前端草稿与保存衔接，不改变后端保存、运行时锁或现场操作；仍不提供跨客户端的原子修订比较。
