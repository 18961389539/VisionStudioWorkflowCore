# 多工位生产可靠性与现场验收

## 工位隔离与全局安全

- 操作员大屏可用 `/?view=operator&stationId=<station-id>` 打开指定工位；生产状态、配置、
  启停/恢复/动作核对、活动告警和留图都使用同一工位 ID。`default` 与不带 `stationId` 的旧链接保持兼容。
- 工位生产告警的来源为 `ProductionRuntime:<station-id>`；PTP 与同步保护按工位独立创建/恢复告警。
- 任一工位存在未决设备动作时，手动动作和生产启动会按设备/机器人/相机 ID 检查冲突。共享资产、
  无法读取的账本、或安全账本缺少资产清单时拒绝动作；互不重叠的资产可以并行，已分类为无硬件副作用
  的纯计算流程不因其他工位的物理设备核对而被全局停机。每个副作用工作流仍须通过自身工位的账本核验。
- 插件扫描/包变更/Worker 操作门禁、健康状态和 `visionstudio_production_locked` 指标按所有工位聚合；
  只读运行指标仍保留默认工位兼容字段。

## 外部触发事件

- `POST /api/production/runtimes/{stationId}/trigger` 在确认队列可写后才接受触发。可用
  `Idempotency-Key` 请求头传 1–128 字符事件 ID；重复 ID 返回既有事件，不重复排队。
- `GET /api/production/runtimes/{stationId}/triggers` 查询事件状态。队列在数据根 `production` 目录中
  按工位耐久保存；默认上限为 1,000 个未完成事件和 10,000 条保留记录。状态文件损坏或队列满时拒绝接受，
  不把信号静默退化成内存成功。
- Pending 事件在工位启动后继续处理。主机重启时处于 Processing 的事件变成 `NeedsReview`，绝不盲目重放；
  对有设备副作用的周期，核对安全账本后由现场系统以新的事件 ID 明确重发。完成状态只在周期追溯耐久提交后记录。
- `MaxCycleMs` 从触发被取出后计时，包含起始追溯登记、执行槽排队与工作流执行；外部信号等待时间不计入单周期预算。
  `lastDurationMs` 以本周期墙钟耗时记录，不再只显示执行器内部耗时。

## 验证样本门槛

数据集发布验收默认要求至少 5 个预期 OK 与 5 个预期 NG 样本。缺少任一类别时对应误判率为 `null`
（不可评估），并阻止验收；不得把“没有 NG 样本”显示成 0% 漏检率。现场策略可以设置更高门槛，
但不能将 `MinimumSamplesPerDisposition` 设为 0。

## 上线前必须完成的物理验收

软件测试不能替代硬件在环 (HIL) 与断电演练。每个设备/工位/触发适配器上线前应留存：

1. 两工位共享 PLC/机器人/相机时的并发互斥测试；不共享资产的工位并行测试。
2. 触发重复 ID、队列满、磁盘只读、服务在 Pending/Processing/追溯提交各阶段被终止后的结果。
3. 设备动作已下发但响应丢失、网络断开、急停、控制器重启时的账本阻断与现场核对证据。
4. 连续 24 小时以上长稳、相机断连/重连、PTP 漂移、磁盘容量临界及 stop timeout 测试。
5. 备份副本不可用、主盘不可用时的恢复演练，并记录实际 RPO/RTO。

Worker 进程隔离目前**不是 OS 权限沙箱**。部署仍需由操作系统账户、ACL、网络分段与设备侧联锁限制
进程权限；在这些控制被现场验证前，不应将任意第三方插件视为受限执行。
