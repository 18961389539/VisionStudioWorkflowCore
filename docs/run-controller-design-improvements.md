# 运行与调试生命周期改进（2026-10-20）

本轮处理编辑器运行、单节点暂存测试、断点会话及切换文档时的并发和资源归属问题。

## 问题与改进

| 原设计问题 | 影响 | 改进 |
| --- | --- | --- |
| 运行/调试只依赖 React busy 状态；仅暂存测试额外有独立 ref | 同一事件内或使用旧回调连续调用时，重渲染前可重复提交，多个入口也不能完全互斥 | 所有编辑器执行和会话删除共用同步 operationRef；busy 状态只负责界面展示 |
| 结束会话无论成功失败都清除 ID | 删除失败后现场和设备租约可能还在，本地已无法重试释放 | 仅成功或 404 时清除；网络/HTTP/超时失败保留 ID、禁用继续执行，并提示再次结束 |
| 新建会话先异步删除旧会话，再立即创建 | 旧删除未完成就可能发生新执行；删除失败还会丢失旧现场 | 已有会话时要求先明确结束；普通运行、一次性调试与暂存测试也不能绕过现有会话 |
| 清空结果不能使在途响应失效 | 模板/流程切换后旧运行正文、继续响应或新建会话会把旧结果重新填回 | 清空时递增结果代次；正文读取后核对操作、代次、取消及挂载状态。普通运行/暂存测试取消，旧会话执行响应不再应用 |
| 静默释放丢失失败反馈 | 文档切换后孤立会话仍占资源，用户看不到释放入口 | 排队释放旧会话；新建会话若在切换后才返回 ID，也只进入释放流程；失败保留会话用于结束重试 |
| 暂存测试使用局部控制器，但顶栏中止只取消普通运行 | 按钮显示“中止”却取消不了节点测试；取消又被统一描述为超时 | 暂存测试接入共享控制器，区分手动取消与 60 秒期限 |
| 仅检查失败响应；成功响应可直接进入结果状态 | 200 的空对象、缺失报告或异常报告可能覆盖旧结果并引发渲染错误 | 检查运行身份、成功标志、有限耗时、节点报告和控制决策；完整算法失败报告仍正常展示 |
| 来源不明的外部结果借用上次提交指纹 | 配方结果可能被误认为当前编辑器参数已验证，并染色同 ID 的画布节点 | 未提供流程快照的结果只在结果区展示，标为当前流程尚未验证，不套用其它运行指纹或画布报告 |
| 结果落地无条件清除节点过期标记 | 参数在运行期间改变时，全局提示过期而节点仍显示新结果 | 节点报告和全局结果使用同一份来源快照判断是否过期 |
| 请求失败后只清节点标记 | 控制连线可能继续动画，误导为仍在执行 | 无有效报告的失败/取消清除执行标记与连线动画 |
| 会话读取默认把未知 state 当作 Completed | 无效成功响应可能将未知会话伪装为已完成 | 核对会话 ID 与后端 Halted/Faulted/Completed 状态；无法确认时保留故障视图和结束入口 |

## 行为边界

- 运行与调试写入不自动重试。会话读取和删除设置 15 秒请求期限，失败在界面保留可操作状态。
- 界面卸载时取消执行请求，并尽力释放已知会话；已发出的有期限删除请求继续完成。卸载后返回的会话 ID 仍尝试删除。
- 若连接断开、服务端没有返回会话 ID，前端无法确认是否已创建；后端已有的取消处理、会话空闲过期及租约管理仍负责最终清理。
- 发送取消请求不能证明物理设备已经停止，提示改为请核对运行追溯和设备实际状态。
- 编辑器模板与加载流程统一通过 clearResult 使结果失效并释放会话；不改变后端执行、设备授权或节点契约。

## 图像目录与预览边界改进（2026-10-21）

- 图像目录的加载中、成功和失败状态统一管理，并同时绑定运行 ID 与重试批次。重试立即撤下旧目录，不再让节点图像或几何尺寸在重新确认期间冒充有效数据；失败仍保留结果提供的最终预览。
- HTTP 200 不再等同于有效目录：检查图像列表、非空节点/端口标识、正整数尺寸及节点内不区分大小写的端口唯一性。响应提供运行 ID 时必须与请求一致。无效响应明确报错，不跳过异常条目或伪造空目录；真正的空列表仍是正常的“未捕获图像”。保留已有的省略运行 ID 和省略端口时使用 `image` 的兼容行为。
- 15 秒期限覆盖请求和正文读取，超时立即结束加载、显示错误并允许重试。旧请求即使忽略取消，迟到响应也不能覆盖超时状态、新请求或其它运行的目录；卸载后不再应用响应。
- 运行 ID、节点 ID 作为 URL 路径段编码，端口名作为查询值编码，避免合法标识中的空格、百分号、井号或问号改变请求目标。
- 自动切换图像来源只依赖选中节点和实际输入/输出可用性，不再受等值节点、连线对象重建影响。用户选择的最终预览或输入模式在普通重渲染时保持不变。
- 工作流预览与节点配置弹窗都直接显示后端错误原因、错误代码和关联号，不再只放在鼠标悬浮提示里；失败只允许显式重试读取目录，不重新执行工作流或设备动作。

## 卡尺几何与图像端口一致性改进（2026-10-21）

- 裁剪变换的基准图像保留实际输入连线的节点和输出端口，不再默认使用同节点的 `image`。端口名按现有契约不区分大小写，图像 URL 与尺寸均取实际捕获的对应端口。
- 只有当前显示的节点和端口与几何坐标来源匹配时，才显示可编辑几何及“适配几何到图像”。普通测量输入必须匹配实际连线；使用卡尺透传输出时，必须是其主 `image` 端口，不能将其它捕获图像视为透传图。
- 基准端口未捕获、手动查看其它输出或回退到最终预览时，不使用其它图像冒充基准，并显示无法编辑的原因及恢复方式。仍可检查其它输出图像，但不在未经确认的图上拖动、重绘或适配测量几何；测量节点的主图结果标注也不会叠加到其它输出端口上。
- 切换到当前测量图像仍只读显示运行报告中的实际变换结果；切回基准时恢复实际连接的图像端口。图像适配使用该端口的真实尺寸，保留既有变换、上游几何及参数校验约束。
